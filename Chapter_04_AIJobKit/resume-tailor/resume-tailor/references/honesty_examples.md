# Honesty Gate — Worked Examples

These are generalized from real sessions. Use them to calibrate how strict to be.

## Example A — Large mismatch, stop and ask

**JD asked for:** 15+ years total experience, 4–5 years leading enterprise QE architecture/consulting practices across multiple clients, board-level dashboards, named advisory work on specific enterprise AI platforms, running 4–8 week external client discovery engagements.

**Candidate had:** 8 years, most recent ~10 months at an "Architect" title, all delivery work for a single internal program, no external client-facing consulting history, no experience with the specific named platforms.

**Correct handling:** Do not tailor silently. Present a short comparison table of match vs. gap, state plainly that inserting "15+ years" or a consulting-practice-lead narrative would misrepresent the candidate and likely fail at interview, and let the candidate choose: tailor to the true ~30% overlap only, treat the role as unrealistic for now, or proceed anyway fully informed. Do not generate a resume file until they pick.

## Example B — Good fit, tailor freely

**JD asked for:** 5–8 years software quality engineering experience, strong automation background (Selenium + an API testing tool), API/web-services testing, leading/mentoring within a delivery team, tracking work in Jira, partnering with Dev/Product/PM.

**Candidate had:** 8 years (top of the stated range), Selenium WebDriver expert, a comparable but not identical API testing tool (RestSharp instead of the JD's named RestAssured — same job, different language ecosystem), direct Jira usage, direct experience partnering with developers/product owners/BAs, and even a relevant domain match (EdTech LMS work vs. an EdTech employer).

**Correct handling:** This is a real match — proceed directly to tailoring. Reword the summary to mirror the JD's own "X to Y years... strong automation background" phrasing (true statement, JD's words). Surface Jira and cross-functional partnering language that was already true but under-emphasized. For the API tool mismatch, don't claim the JD's named tool — write it as "RestSharp (the .NET equivalent of RestAssured)" so the reader understands the transferable skill without a false claim. Highlight every one of these insertions in yellow.

## Example C — Mid-session correction from the user

Partway through tailoring, the candidate says "I also have Java, C++, and Fiddler experience" — none of which were in the original master resume.

**Correct handling:** Treat this as new ground truth, not fabrication risk. Add the specific things stated (Java, C++, Fiddler) to the skills section and, where it fits naturally, the summary — highlighted, since they're new insertions for this tailored version. Do not inflate "I have experience with X" into "expert in X," and don't invent a project or metric around the new skills unless the candidate volunteers one. If a stronger placement (a full bullet under a specific role) would help, offer it, but only fill in specifics the candidate actually gives you.

## Quick self-check before generating any tailored resume

1. Did I compare the JD's *overall* seniority/function bar to the resume's *overall* level, not just individual keywords?
2. Is every yellow-highlighted phrase traceable to something true, transferable-and-labeled, or user-confirmed?
3. Did I leave out anything that's a genuine gap, rather than papering over it?
4. If I found a large mismatch, did I stop and ask instead of deciding for the user?
